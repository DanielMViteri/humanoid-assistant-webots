# ROS2 Node Plan

## Active Architecture

Each ability should be a separate Python ROS2 node. Nodes communicate through topics and, where needed, services.

```text
input_node
  -> /user/input_text

nlp_node
  subscribes: /user/input_text
  publishes:  /assistant/response_text
              /user/mood_state

tts_node
  subscribes: /assistant/response_text
  publishes:  /assistant/speech_status

session_node
  subscribes: /user/input_text
              /assistant/response_text
              /user/mood_state
  writes:     local session log

dashboard_node
  reads/subscribes: session, mood, telemetry, alerts

telemetry_node
  publishes: /robot/telemetry
```

## MVP Topics

| Topic | Purpose |
|---|---|
| `/user/input_text` | Raw text from typed or voice input |
| `/assistant/response_text` | Text response generated by NLP node |
| `/user/mood_state` | Structured mood/intent result |
| `/assistant/speech_status` | TTS playback status |
| `/robot/telemetry` | Robot/system telemetry |
| `/system/alerts` | Warnings or follow-up alerts |

## OpenAI API Role

Use OpenAI in the MVP for:

- response generation
- mood/intent classification
- structured JSON output

Do not hardcode API keys. Use `OPENAI_API_KEY` as an environment variable.
